# kotlin-ecshopx 开发步骤（M0/M1/M2 · P0/P1/P2）

> 版本：v1.0 · 排期依据：[URL 列表 §2/§3](./04-URL列表文档.md) 的优先级分层；里程碑 M 为**工程推进步**，优先级 P 为**功能交付层**，对应关系 M0⇦P0、M1⇦P1、M2⇦P2。

## 0. 总览

```
M0 骨架与核心交易闭环   ── P0 全部功能（≈120 端点：商品→购物车→订单→支付(mock/余额/积分)→会员→后台基础）
M1 完整交易与营销经营   ── P1 功能（售后、券/满减/拼团/秒杀、店铺分销、积分储值、评价、真实微信支付）
M2 生态与长尾对接       ── P2 功能（openapi/ERP/渠道支付族/结算/砍价签到抽奖/其余长尾端点）
验收锚点：每步含"可运行产物 + 测试门槛"，未过门槛不进入下一步。
```

## 1. M0 —— 工程骨架 + 核心交易闭环（P0）

### M0-1 工程初始化
工作：根 parent pom（`${revision}`、dependencyManagement、kotlin-maven-plugin+spring 插件、阿里云镜像）；建 `ecshopx-common/dao/service/web-admin/web-front/boot` 六 module 与包骨架；`application.yml`（H2 file 数据源、`spring.sql.init` 指向 `sql/schema.sql`+`sql/seed.sql`）；`.gitignore`、`mvnw`。
产物：`mvn -q verify` 全模块编译通过，boot 可起（/actuator/health UP，H2 自动建 70 表）。
门槛：空 Controller 冒烟 200；schema/seed 在空库重放无错（幂等 `CREATE TABLE IF NOT EXISTS` 已具备）。
> 已踩坑（2026-10-15 修复）：fat jar + H2 **file** 库组合下 `spring.sql.init.mode: embedded` 会**静默跳过**建表脚本（16KB 空库；同 jar 改 `always` 即建满 70 表；mem 库单测下 embedded 正常，AUTO_SERVER 已排除）。解决：yml 用 `mode: always` + `classpath*:/sql/*.sql`（嵌套 jar 需通配），seed 尾句用 `GREATEST(current_value,100000)` 防止重启回拨号段。验证：空 `data/` 起 jar → 70 表/种子/seq=100000；手工推进号段后重启不回退。

### M0-2 横切基座
工作：`ApiResponse/PageResult/PageQuery/PageHelper`、`GlobalExceptionHandler`+`BizException/ErrorCode`、校验错误→errors 映射、`Money/TimeSec` 工具、`StampInterceptor`(created/updated)、`SeqGenerator`+`seq_generator` 表、`Db.transactional` DSL、Jackson snake_case 配置、`force-ok-status` 兼容开关。
产物：common+dao 单测（分页三态、号段并发 50 线程无重号、DSL 回滚）。
门槛：JaCoCo 对 common ≥80%。
> M0-2 完成记录（2026-10-15，commit 262c14e）：39 测试全绿、common 行覆盖 93.65%。踩坑：① H2 2.2 无 `UPDATE…RETURNING`，号段用同事务 UPDATE(行锁)→SELECT 两步；② `@Component` 构造参数带 Kotlin 默认值会生成多重构造器，Spring 报 "No default constructor found"——`@Value` 参数不要写默认值；③ mem H2 测试 URL 必须 `DB_CLOSE_DELAY=-1`，否则 setup 连接关闭后库即销毁；④ `spring.sql.init` 的 `mode=embedded` 在 fat jar+file 库同样静默跳过（见 M0-1 注）。

### M0-3 鉴权与租户
工作：4 组 `SecurityFilterChain`；`JwtFilter`+jjwt 签发/刷新（AUTH-1/2/3、AUTH-4 local 分支+mock wxapp 分支）；`Principal`、`TenantFilter`、`@RequiresResource` AOP + roles/resources 缓存；`operator_logs` 审计 AOP（shoplog 等价）；验证码 mock。
产物：AUTH 5 端点全通；后台/消费者越权用例（A 租户令牌访问 B 资源 403/404）。

### M0-4 商品域
工作：items/category/attribute(s)/barcode/tags/servicelabels/shipping_templates 的 DO+Mapper+Service+后台 CRUD（GOODS-1..6，含多规格 spec_items 组装、`is_sku` 展平、预警库存、元/分兼容筛选）；前台公开 GOODS-7/8（详情聚合按 URL 文档 §2.2）；分类树缓存（Caffeine）。
产物：后台建多规格商品→前台列表/详情出参字段与 PHP 样本结构 diff 通过（契约测试框架在本步建立）。

### M0-5 购物车与算价引擎
工作：orders_cart CRUD（CART-1..6，多店铺分组视图）；`PriceContext`+`MarketingEngine` 责任链（M0 只挂：商品价、会员折扣、满减满折骨架、运费模板计算、券开关位）；ORDER-1 预览端点。
门槛：**预览价==下单价**属性测试（随机购物车×券×等级 1000 例）。

### M0-6 订单创建与状态机
工作：`OrderStatusMachine`（迁移表+文案表）；ORDER-2/3（幂等 token、CAS 扣库存、拆单暂不——单店铺单，`original_order_id` 列预留）；订单取消/超时自动取消（@Scheduled+ShedLock-JDBC）；ORDER-4..8 查询族 + 后台订单族（列表/详情/备注/发货 ORDER-9）；`orders_operate_logs` 全流转留痕。
门槛：并发 50 单同库存不超卖；超时关单回补库存+还券用例。

### M0-7 支付闭环（mock/point/deposit/offline）
工作：`trade` 表服务、`PayChannel` 抽象 + `MockChannel`/`PointChannel`/`DepositChannel`/`OfflineChannel`；PAY-1..4；PAY-5 mock 回调端点（本地模拟渠道通知，验证幂等）；`OrderPaidEvent`→积分入账/佣金流水占位/角标。
产物：H5 模拟全流程「加购→预览→下单→余额支付→回调→发货→收货」E2E 脚本跑通。

### M0-8 会员与支撑收尾（P0 完成线）
工作：MEM-1..8；收藏/浏览/地址；upload_files+本地 storage 静态映射；sys_config 读写 SUP-1/2/4；seed 演示数据核对；部署脚本 `run.bat/run.sh`+README 快启。
门槛：URL 文档 §2 的 P0 端点全部 MockMvc 契约绿；附录 P0 标注同步勾选。

**M0 退出标准**：演示租户可完成真实购物闭环（mock 支付）；`mvn verify` 全绿；H2 单文件重启数据不丢。

## 2. M1 —— 完整交易与营销经营（P1）

### M1-1 售后域
aftersales/aftersales_detail/aftersales_refund 三表服务；状态机（申请→审核→退货→确认→退款→完成/关闭）；退款执行接 `PayChannel.refund`（mock→真实原路退）；回写 trade/订单/积分/佣金冲销事件；P1 售后端点 ≈20 条 + 后台审核 UI 数据。
门槛：部分退款多次申请、剩余可退额守恒用例。

### M1-2 真实微信支付 + 支付宝沙箱
wechatpay-java SDK 适配 `WxChannel`（JSAPI 下单/回调验签解密/查单/退款），`ecx.pay.active-channel-profile` 切换；Alipay 沙箱 profile；`offline_payment` 审核流后台。
门槛：沙箱真单全链路；回调乱序/重复/伪造签名用例。

### M1-3 营销完整版
优惠券（CRUD/领取/锁定/核销/过期回收，`promotions_coupon(_user)`）；满减满折配置台与 RuleParser 兼容 PHP `discount_config` 存量 JSON；秒杀（活动/商品/锁库存 validity_period）；拼团（开团/参团/成团失败自动退，@Scheduled 结算）；下单链挂接全部优惠且与预览同源。
门槛：优惠叠加矩阵用例（券×满减×会员折×积分上限）；拼团并发成团/超员。

### M1-4 店铺与分销
distributor CRUD+审核、店铺商品（价格/库存/上下架 `is_total_store` 双模）、导购（salesman+role+`x-wxapp-session` 员工端链，员工端 ORDER 族）、佣金 `distribute_logs`（支付入账/退款冲销/结算 close）、提现申请-审核-打款(mock)、自提点+核销（ziti_code）。
门槛：多店铺混合购物车拆单展示与 distributor_id 过滤越权用例。

### M1-5 积分/储值/评价/发票(简)
积分规则（下单得/抵扣上限 ratio/签到位预留）、余额充值（CZ 单+充值规则赠品）、`trade_rate` 提交/回复；`orders_invoice` 申请单 CRUD；数据权限 datapass 脱敏（VO MaskedString）。
门槛：积分/余额账实相符（流水和对账脚本：Σlog==account）。

**M1 退出标准**：P1 端点契约绿；真实微信支付可开关；一套演示店铺（总部+1加盟）可运营演示。

### M2-3 长尾端点与营销扩展

### M2-4 生产化

**M2 退出标准**：附录 2199 端点中「P0/P1 全量 + P2 已承诺清单」可运行；MySQL 形态与 H2 形态双跑通同一测试套件。

## 6. 完成记录（追加）

### M0-3 鉴权与租户 —— 已完成（2026-10-15）

范围：AUTH-1..5 五端点（operator login / token refresh / invalidate、h5app new_login / h5app token refresh）、双 SecurityFilterChain（admin 链 `/api/**`、front 链 `/api/h5app/**`）、JWT(HS256, jjwt 0.12.6) + Principal/Kind + TenantContext、@RequiresResource 资源权限切面（admin 类型放行，其余 operator→role→resource 闭包，Caffeine 5m 缓存）、@Audited 审计写 operator_logs、seed 追加 viewer 账号（无角色，越权用例）。

验收：`mvn verify` 全绿 53 测试（含 AuthEndToEndTest 14 项：401/403/400/刷新轮换/跨面拒绝/is_new 语义/审计行数）；fat-jar + 文件 H2 实跑登录→刷新→登出→匿名 401 通过（探针控制器属 test 源集，不进 fat jar，403 语义由 MockMvc 覆盖）。

踩坑（实测）：
1. **Kotlin 切面参数绑定静默失配**：`@Around("@annotation(rc)")` 依赖反射参数名；Kotlin 默认不写 MethodParameters 属性，导致切面永不命中、controller 不代理、越权请求直接 200。修复=切点改全限定名形式 `@annotation(com.ecshopx.kotlin.common.security.RequiresResource)`，方法体内 `MethodSignature.method.getAnnotation(...)` 取注解。
2. **schema.sql 的 `SET SCHEMA ECX` 只是会话级**：连接池其余连接默认 schema 仍是 public，mapper 非限定表名在新连接上报 Table not found。曾试 URL `INIT=...\;SET SCHEMA` —— Spring 属性层吞反斜杠截断 URL（报 URL format error）；H2 2.2 也不支持 `ALTER USER SA SET SCHEMA`。最终方案=部署脚本不再显式建/切 schema，表落默认 public（MySQL 部署选库即等效），BootSmokeTest 断言改 `table_schema='public'`。
3. MockMvc `andReturn().response.contentAsString` 对无 charset 响应按 Latin-1 解码中文出乱码，断言文案一律用 jsonPath（字节级）。
4. Boot 3.3.4（Spring 6.1）无 MockMvc Kotlin DSL（`mvc.post{}/andExpect{}` 为 6.2+），端到端测试用 MockMvcRequestBuilders/ResultMatchers 经典 API。
5. `-java-parameters` 已加入根 pom Kotlin args（对 Jackson/参数名解析有益，切面不再依赖它）。
