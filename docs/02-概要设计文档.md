# kotlin-ecshopx 概要设计文档

> 版本：v1.0 · 上位文档：[架构设计](./01-架构设计文档.md) · 下位文档：[详细设计](./03-详细设计文档.md)

## 1. 系统定位与角色

kotlin-ecshopx 是 ECShopX 电商交易核心的 Kotlin 重写版，支持四类操作者：

| 角色 | 入口 | 源系统对应 |
|---|---|---|
| 平台运营/管理员 | `/api/**`（后台 SPA） | routes/api + `jwt` provider（operator_type=admin/staff） |
| 店铺（分销商/门店） | 同上（distributor 视角）+ 员工端 | operator_type=distributor；`distribution_distributor` |
| 店铺员工/导购 | `/api/admin/wxapp/**` 小程序 | `adminwxapp` provider（x-wxapp-session） |
| 消费者 | `/api/h5app/**`、`/api/wxapp/**` | `wxapp`/公开 + `dingoguard:h5app` |

租户模型三级：**company（租户）→ distributor（店铺/门店）→ shop（点位）**。独立部署 company_id=1。

## 2. 领域划分与源系统映射

50 个 PHP Bundle 收敛为 9 个领域模块 + 2 个支撑模块，落位在 `ecshopx-service` 的包结构：

| 领域模块 | 责任 | 源 Bundle | 优先级 |
|---|---|---|---|
| company 租户与权限 | 公司、运营账号、角色资源、激活、操作日志 | CompanysBundle, SuperAdminBundle(账号部分) | P0 |
| member 会员 | 注册/登录、资料、地址、等级、收藏、浏览、发票抬 | MembersBundle | P0 |
| point/deposit 积分与余额 | 积分账户/流水、储值余额/充值/抵扣 | PointBundle, DepositBundle | P1 |
| goods 商品 | SPU/SKU、分类、属性/规格、条码、标签、服务属性、运费模板 | GoodsBundle | P0 |
| cart 购物车 | 多店分组购物车、勾选、加价购上下文 | OrdersBundle(Cart) | P0 |
| order 订单 | 下单/算价/拆单、状态机、发货、取消、评价、发票申请 | OrdersBundle(除 Cart) | P0 |
| trade 支付 | 支付单、渠道抽象(wx/alipay/point/deposit/offline)、回调、退款执行 | PaymentBundle + trade/offline_payment 表 | P0(核心渠道) |
| aftersales 售后 | 售后申请/审核/退货退款状态机 | AftersalesBundle | P1 |
| promotion 营销 | 满减满折、优惠券、秒杀、拼团、 bargain(砍价后做)、会员价 | PromotionsBundle, KaquanBundle(券) | P1(券/满减 P0) |
| distributor 店铺分销 | 店铺、员工、商品上下架/店铺库存、佣金流水、提现、自提点 | DistributionBundle, SalespersonBundle(基础) | P1 |
| statement 结算 | 账期、对账单 | OrdersBundle(Statements) | P2 |
| support 支撑 | 上传文件、系统配置、号段、审计、缓存、定时任务 | EspierBundle | P0 |

明确裁剪（保留扩展点不实现）：CrossBorder/医药(处方)/Community 团购头/EmployeePurchase/Kujiale/Shuyun/Youshu/TbItems/ShopexAI/Wsugc/Im/WorkWechat/各聚合支付渠道分账/SystemLink ERP/Openapi 签名网关（P2 只做接口骨架）。

## 3. 核心域模型

聚合与主要实体（表级 ER 见 §6，字段见[详细设计](./03-详细设计文档.md)与 [`sql/schema.sql`](../sql/schema.sql)）：

```
company 1─n operators n─m roles n─m resources          （权限闭包：operator→role→resource_code）
company 1─n members 1─1 members_info 1─n members_address
goods:  items_category(树) ─┐
        items(SPU goods_id / SKU item_id, is_default) ─┴─ items_rel_attributes(规格/参数值)
        shipping_templates ── items.templates_id
cart:   orders_cart(user_id, shop_type+shop_id 分组, activity 上下文)
order:  orders_normal_orders(1) ─ orders_normal_orders_items(N)
        orders_associations(全渠道单号路由) · orders_operate_logs · orders_delivery(1─N items)
        trade(N)─orders(1) 支付单 ; offline_payment ; orders_cancel_orders
afters: aftersales(1)─aftersales_detail(N)─aftersales_refund(1)
promo:  promotions_marketing_activity─items/coupons: promotions_coupon─promotions_coupon_user
        seckill/groups(team─member)
dist:   distribution_distributor─distributor_items(店铺价/库存)─salesman─pickup_location
        distribution_distribute_logs(佣金)─cash_withdrawal
money:  point_member/point_member_log · user_deposit/deposit_trade · statements/statement_details
```

订单状态机（沿用源系统字符串枚举，Kotlin `enum` 映射）：

```
pay_status:     NOTPAY → PAYED → (退款) REFUND_PART/REFUND
order_status:   NOTPAY → PAYED → PACKING → WAIT_BUYER_CONFIRM → DONE
                     └→ CANCEL(超时/用户取消)   groups 类前置 WAIT_GROUPS_SUCCESS
delivery_status:PENDING → PART_DONE/PACKED → DONE
cancel_status:  NOCANCEL → CANCEL_APPLY →CANCEL_AGREE/ REFUSE_CANCEL
```

实现方式：`OrderStatusMachine` 白名单表（from,event→to），迁移/流转集中校验，替代 PHP 散落在 171 个 service 里的 if 判断。

## 4. 核心业务流程（概要时序）

### 4.1 下单支付（P0 主链路）

```
消费者端:
 1. POST /api/h5app/wxapp/cart                加车（校验 onsale/店铺库存，落 orders_cart）
 2. POST /api/h5app/wxapp/getFreightFee       结算预览（服务端算价：商品额→活动→券→会员折→积分→运费，
                                              返回与 PHP 同构的 preview 对象，客户端不算钱）
 3. POST /api/h5app/wxapp/order_new           创建订单（事务：取号→锁库存条件更新→写订单+明细+
                                              促销快照→清车→写日志；point/deposit 支付在此步内结清）
 4. POST /api/h5app/wxapp/payment             支付（pay_type=wxpay → 渠道预下单 → 返回 JSAPI 参数包）
 5. (渠道回调) POST /api/notify/wechat/pay     验签→trade 置 SUCCESS(条件更新幂等)→
                                              AFTER_COMMIT 事件：加积分/佣金流水/发货通知
 6. GET  /api/h5app/wxapp/payment/query        前端轮询兜底
超时链路：@Scheduled 每分钟扫 auto_cancel_time<now → 关单还库存（源系统同构）
```

### 4.2 售后退款（P1）

```
申请 aftersales → 商家审核(同意/拒绝) → 用户退货/填单号 → 商家确认收货 →
aftersales_refund(READY→AUDIT_SUCC) → 渠道退款执行(wx/alipay/原路) → 回调/轮询 →
SUCCESS：回写 trade.refunded_fee、订单 refund 状态、退积分/佣金冲销（同一事件的多个 listener）
```

### 4.3 商家发货（P0）

```
POST /api/orders/delivery：整单/拆包 → orders_delivery+items → 明细 delivery_item_num 累计 →
全部发完 delivery_status=DONE → operate_log → （物流跟踪 trackerpull P2 对接）
```

## 5. 接口设计概要

- 四 Surface 的鉴权与权限模型见[架构 §4](./01-架构设计文档.md)；
- 全量 2199 个 PHP 端点清单在[附录](./附录-ECShopX全量路由清单.md)，作为迁移对照；
- Kotlin 版**首发接口集（P0 ≈120 端点）**逐条 URL/方法/入参/出参见 [04-URL列表文档](./04-URL列表文档.md)；P1/P2 端点在该文档 §7 按模块给出摘要与增量规格；
- 命名沿用源系统（snake_case 出入参、`item_id` 等），新接口不再引入 camel/snake 混用（源系统 `pageSize`/`page_size` 并存，Kotlin 版两者都收、`page_size` 优先）。

## 6. 数据架构

10 个域、70 张核心表（完整 DDL：[`sql/schema.sql`](../sql/schema.sql)，演示数据：[`sql/seed.sql`](../sql/seed.sql)）：

| # | 域 | 表（源表名保留） |
|---|---|---|
| 1 | 平台权限 | company, operators, roles, resources, operator_rel_roles, role_rel_resources, operator_logs |
| 2 | 会员 | members, members_info, members_grade, members_address, members_associations, members_items_fav, members_browse_history, members_invoices |
| 3 | 积分/余额 | point_member, point_member_log, user_deposit, deposit_trade, deposit_recharge_rule |
| 4 | 商品 | items, items_category, goods_items_rel_cats, items_attributes, items_attribute_values, items_rel_attributes, items_barcode, items_tags, items_rel_tags, items_rel_type, servicelabels, shipping_templates |
| 5 | 购物车/订单 | orders_cart, orders_normal_orders, orders_normal_orders_items, orders_associations, orders_rel_promotions, orders_operate_logs, orders_cancel_orders, orders_delivery, orders_delivery_items, orders_invoice |
| 6 | 支付 | trade, offline_payment |
| 7 | 售后 | aftersales, aftersales_detail, aftersales_refund |
| 8 | 营销 | promotions_activity, promotions_marketing_activity(+items), promotions_coupon, promotions_coupon_user, promotions_seckill_activity(+rel_goods), promotion_groups_activity, promotion_groups_team(+member) |
| 9 | 店铺分销 | distribution_distributor, distribution_distributor_items, distribution_distributor_salesman, distribution_distribute_logs, distribution_cash_withdrawal, distribution_pickup_location |
| 10 | 结算/支撑 | trade_rate(+reply), statements(+details), sys_config, upload_files, seq_generator |

与源库差异（重写许可的规整）：合并了发票 4 表为 1 表（M0 简化）、砍掉药品/跨境/海关列但保留 `type` 判定列、`orders_*` 子类订单（service/bargain）统一进 normal + `order_class` 列、优惠券在 KaquanBundle 旧模型之上重建为 `promotions_coupon(_user)`。其余列名、单位、语义与 PHP 一致，保证并行期可用脚本双向同步。

数据量假设（单机学习/小型店铺）：商品 <10 万、订单 <100 万——H2 单文件足够；索引按源系统 `@ORM\Index` 还原。

## 7. 迁移与并行策略

1. **接口级绞杀**：网关（或小程序基址配置）按 URL 白名单把已迁移端点指向 Kotlin 服务，其余仍走 PHP；P0 清单即白名单第一版；
2. **数据迁移**：PHP MySQL → H2 用一次性 ETL 脚本（列同名，直导；json_array/CLOB 原样）；并行期以 PHP 为写主，Kotlin 只读灰度，联调通过后按域切换写主；
3. **契约测试**：以[附录路由清单](./附录-ECShopX全量路由清单.md)为基线，对 P0 端点录制 PHP 响应样本，Kotlin 侧断言 JSON 结构等价（字段名级别，值允许时间戳差异）。

## 8. 非功能要求

| 项 | 指标/约定 |
|---|---|
| 启动 | 冷启动 <15s（H2 file），首次自动建表+seed |
| 并发 | 单机 200 QPS 读 / 50 TPS 下单（H2 文件模式，超出即触发 §6 升级路径） |
| 安全 | JWT HS256（密钥走环境变量）、BCrypt 口令、参数化 SQL、越权用 company_id+principal 双断言 |
| 可观测 | Spring Boot Actuator + logback JSON；订单/售后关键流转 100% 落 operate_logs |
| 兼容 | JDK17+，Windows/Linux；浏览器无关（纯 API） |
