## 3. Kotlin 事务支持

### 3.1 声明式：@Transactional 约定

```kotlin
@Service
class OrderCreateService(...) {
    @Transactional                              // 默认 REQUIRED + READ_COMMITTED
    fun createOrder(cmd: CreateOrderCmd): OrderCreated { ... }

    @Transactional(readOnly = true)
    fun getOrderDetail(orderId: Long, principal: Principal): OrderVO { ... }
}
```

- 只标 **public 编排方法**；private/内部调用不过代理 → 需要独立事务时拆 Bean 或用 3.2 DSL；
- kotlin-maven-plugin 启用 `spring` 编译器插件（类/方法自动 open），无需 open 关键字；
- rollback 语义用默认（RuntimeException 回滚）；`BizException` 继承 RuntimeException，受检回滚天然覆盖。

### 3.2 模板式：`Db` DSL（对应 PHP beginTransaction/commit/rollback 718 处的收编）

```kotlin
// service/tx/DbTransactional.kt
@Component
class Db(private val txManager: PlatformTransactionManager) {
    fun <T> transactional(
        propagation: Propagation = Propagation.REQUIRED,
        block: () -> T,
    ): T {
        val tt = TransactionTemplate(txManager)
        tt.propagationBehavior = propagation.ordinal
        tt.setIsolationLevelName("ISOLATION_READ_COMMITTED")
        return tt.execute { block() } ?: error("tx returned null")
    }
    /** 提交后执行（外部 HTTP / 发事件），回滚则不执行 */
    fun afterCommit(block: () -> Unit) =
        TransactionSynchronizationManager.registerSynchronization(
            object : TransactionSynchronization {
                override fun afterCommit() = block()
            })
}
```

用法（支付回调幂等 + 事务外通知）：

```kotlin
fun onPayNotify(n: WxNotify): String = db.transactional {
    val updated = tradeMapper.markSuccess(n.tradeId, n.transactionId, n.payFee) // UPDATE…WHERE trade_state='NOTPAY'
    if (updated == 0) return@transactional NotifyResult.DUP                // 幂等：条件更新 0 行即重复
    orderMapper.markPayed(n.orderId)
    db.afterCommit { publish(OrderPaidEvent(n.orderId)) }
    NotifyResult.OK
}
```

### 3.3 事务边界矩阵（核心流程）

| 流程 | 事务内 | 事务外（afterCommit/@Async） |
|---|---|---|
| 加购物车 | 单表单写（不开显式事务） | — |
| 创建订单 | 取号·条件扣库存·订单+明细+促销快照+操作日志·清车 | 渠道预下单、消息 |
| wxpay 支付 | trade NOTPAY→SUCCESS·订单 payed·积分入账·佣金流水 | 调渠道查询确认、通知 |
| 余额/积分支付 | 扣减+结清同一事务（条件 UPDATE 防负） | — |
| 发货 | delivery+items·明细发货数·状态迁移·日志 | 物流订阅 |
| 售后审核/退款 | 状态机流转+refund 单·回写 trade.refunded_fee | 渠道退款调用（结果由第二次事务落库） |
| 超时取消扫描 | 每单一个 REQUIRES_NEW 小事务（失败不阻塞批次） | — |

并发控制基线：**一律条件 UPDATE（CAS 语义）+ 影响行数判断**，示例：库存 `UPDATE items SET store=store-? WHERE item_id=? AND store>=?`；积分/余额同理带 `AND balance>=?`。H2 与 MySQL 行为一致，不依赖方言锁语法。

## 4. DAO 层分页工具类封装

### 4.1 对外 API（common 模块，Web/Service/DAO 共用）

```kotlin
// common/api/PageQuery.kt
data class PageQuery(val page: Int, val pageSize: Int) {
    companion object {
        const val MAX_SIZE = 100                    // 后台 PHP 校验 50，统一放宽到 100 并截断
        fun of(page: Int?, pageSize: Int?, defaultSize: Int = 10): PageQuery = PageQuery(
            page?.coerceAtLeast(1) ?: 1,
            (pageSize ?: defaultSize).coerceIn(1, MAX_SIZE)
        )
    }
    val offset: Long get() = (page - 1).toLong() * pageSize
}
// Controller 绑定：同时收 pageSize / page_size（源系统双写法）
data class PageParam(
    val page: Int? = null,
    @get:JsonProperty("pageSize") val pageSizeA: Int? = null,
    @get:JsonProperty("page_size") val pageSizeB: Int? = null,
) { fun toQuery(default: Int = 10) = PageQuery.of(page, pageSizeA ?: pageSizeB, default) }
```

### 4.2 分页执行模型：`PageHelper.paginate`（显式，不依赖 ThreadLocal）

源系统是 Repository 手写 `setFirstResult/setMaxResults` + 独立 COUNT；Kotlin 版保留同样的**显式**风格，避免 PageHelper-ThreadLocal 在异步/嵌套调用下丢页的坑：

```kotlin
// dao/paging/PageHelper.kt
object PageHelper {
    /**
     * @param countSql 与 dataSql 相同 WHERE 的 count 查询（可为 null → 跳 count，用于游标式/前端不需要总数的场景）
     */
    fun <E, T> paginate(
        pq: PageQuery,
        count: () -> Long?,
        query: (offset: Long, limit: Int) -> List<E>,
        map: (List<E>) -> List<T> = { it },
    ): PageResult<T> {
        val total = count()?.let { if (it == 0L) return PageResult(0, emptyList()) else it }
        val rows = query(pq.offset, pq.pageSize)
        return PageResult(total ?: (pq.offset + rows.size + if (rows.size == pq.pageSize) 1 else 0).toLong(), map(rows))
    }
}
```

Mapper 侧只要求两条语句可注入参数 `offset/limit`：

```kotlin
interface ItemsMapper {
    fun countByQuery(q: ItemsQueryDO): Long
    fun listByQuery(q: ItemsQueryDO): List<ItemsDO>       // WHERE 片段共用 <sql id="qWhere">，尾部 LIMIT #{offset 转 limit},${pageSize}
}
```

```xml
<!-- resources/mapper/ItemsMapper.xml：count 与 data 共享 WHERE include，杜绝两端口径漂移 -->
<sql id="qWhere">
  WHERE i.company_id = #{companyId}
  <if test="approveStatus != null">AND i.approve_status = #{approveStatus}</if>
  <if test="keyword != null">AND (i.item_name LIKE #{kw} OR i.item_bn = #{keyword} OR EXISTS(
      SELECT 1 FROM items_barcode b WHERE b.item_id = i.item_id AND b.barcode = #{keyword}))</if>
  <if test="categoryId != null">AND EXISTS(SELECT 1 FROM goods_items_rel_cats c
      WHERE c.item_id = i.item_id AND c.category_id = #{categoryId})</if>
</sql>
<select id="countByQuery" resultType="long">SELECT COUNT(*) FROM items i <include refid="qWhere"/></select>
<select id="listByQuery" resultType="ItemsDO">
  SELECT i.* FROM items i <include refid="qWhere"/>
  ORDER BY <choose><when test="sort=='price'">i.price</when><otherwise>i.sort DESC, i.item_id DESC</otherwise></choose>
  LIMIT #{offsetSize}
</select>
```

（H2/MySQL `LIMIT ?` 单参 = `LIMIT offset, size` 的等价写法：XML 里用 `LIMIT #{offsetVal}` 前置拼接 `OFFSET`，或按 profile 方言；`PageDialect` 统一封装。）

### 4.3 MyBatis 拦截器（可选增强：对无法拆 count/data 的复杂 JOIN）

```kotlin
@Intercepts(QueryTimeoutExecutor::class)
class PageInterceptor : Interceptor {
    // plugin: Executor.query 若参数携带 PageQuery →
    //   1) SELECT COUNT(*) FROM ( 原SQL ) t  —— 去掉 ORDER BY 后执行
    //   2) 原SQL LIMIT offset,pageSize 追加
    //   3) 返回 PageResult；ThreadLocal 仅在此拦截器内部短生命周期使用
}
```

规则：**简单单表/两表用 4.2 显式双语句；确需对多表 JOIN 结果分页时才走拦截器**，拦截器改写 count 时剔除 ORDER BY 与 1:1 LEFT JOIN。

## 5. 号段生成器（业务单号）

```kotlin
// service/seq/SeqGenerator.kt
@Component
class SeqGenerator(private val mapper: SeqGeneratorMapper, private val node: Int = 1) {
    /** 与 PHP 对齐：order_id=16 位 = yyMMddHHmmss(12) + 序列(4)；trade_id 前缀 T；refund R */
    fun next(name: SeqName): Long = db.transactional(Propagation.REQUIRES_NEW) {
        val seg = mapper.takeSegment(name.name)      // UPDATE seq_generator SET current_value=current_value+100, version=version+1 WHERE …
        val base = mapper.selectValue(name.name)
        TimeSec.nowStamp14() * 1 + (base % 10000)    // 实现细节：号段+时间前缀，测试可注入时钟
    }
}
```

步长 100 取段 + 内存游标，单实例足够；多实例时 node 位区分类 PHP `get_order_id` 的生成规则，**位数与可排序性保持源系统一致**（列表按 order_id 排序即按时间排序）。

## 6. 鉴权与多租户组件

```kotlin
data class Principal(
    val kind: Kind,               // OPERATOR|MEMBER|SALESMAN|SUPER
    val id: Long, val companyId: Long,
    val operatorType: String? = null,
    val distributorIds: List<Long> = emptyList(),
    val openId: String? = null,
)
```

- `JwtFilter`：解析 Bearer → `Authentication`；claims 里只放 `sub/kind/company_id`，账号明细走 Caffeine(`operatorCache`, TTL 5m)——对应 PHP `app('authorization')->getUserData` 每请求全量回查；
- `SecurityFilterChain` × 4：按 §架构-4 的路径划分；公开白名单 = 附录中 providers 为空的 frontnoauth 端点（商品浏览、登录、支付回调）；
- `TenantFilter`：注入 `companyId`；独立部署恒 1；断言 DTO.companyId（如后台切换店铺）∈ principal.distributorIds，否则 403；
- `@RequiresResource("goods.items.lists")` + AOP：查 `role→resource_code` 闭包（缓存），复刻 `CheckActivedMiddleWare::checkPermission`；资源 code 直接沿用附录路由表 `as` 命名；
- 当前选中店铺：`GET/PUT /api/distributor/select`（源=Redis key）→ Kotlin 写回 operators.distributor_ids 关联的会话态表 `sys_config(user:{id}:select_distributor)`，或直接以后端无状态 + 请求参数 `distributor_id` 为准（默认后者，行为差异在 URL 文档标注）。

## 7. 核心服务详细设计

### 7.1 算价引擎（价格一致性唯一出口）

`PriceContext` 输入（items×num、会员等级、券、积分开关、活动集合、店铺价、运费模板+地区），输出与 PHP `getFreightFee` preview 同构的对象；责任链固定顺序（与源系统一致）：

```
商品基础额(店铺价/活动价覆盖) → 满减/满折(marketing) → 优惠券 → 会员折扣 →
积分抵扣上限校验 → 运费(shipping_templates 规则 + 包邮活动) → 佣金预估(rebate) → 汇总 total_fee
```

每步产出 `discount_info[]`（type/rule/discount_fee）与订单快照落 `orders_rel_promotions`；**下单与预览走同一实例**（PHP 两处实现漂移是已知坑，代码审查项 CR-1）。

### 7.2 创建订单（OrderCreateService.createOrder 步骤化）

```
1  入参校验+幂等（fastbuy/cart 模式分流；client_token 幂等表 sys:order:idem:{token} SETNX 语义）
2  读购物车/明细 → PriceContext 全量服务端重算（拒绝信任前端金额，与 PHP 相同但入参禁止传 price）
3  事务开始
   3.1 SeqGenerator.next(ORDER)（REQUIRES_NEW，见 §5）
   3.2 逐明细条件扣库存（店铺单走 distribution_distributor_items.store；赠品/加购价校验）
   3.3 INSERT orders_normal_orders / items / associations / rel_promotions
   3.4 DELETE 对应 orders_cart；UPDATE 券状态 UNUSED→LOCKED
   3.5 operate_logs(create)
4  事务提交
5  pay_type ∈ {point, deposit} → 走 §7.3 即时结清（第二事务）；否则返回待支付
6  afterCommit：发 OrderCreatedEvent（通知/统计 listener 挂点）
```

### 7.3 余额/积分支付（复用 deposit/point 表）

`UPDATE user_deposit SET deposit_amount=deposit_amount-? WHERE user_id=? AND deposit_amount>=?` → 0 行即余额不足 `BIZ`；同事务写 `deposit_trade`（TD 前缀单号，`CZ` 为充值）+ 结清订单。与 PHP `payment_deposit`、`pay_type=point` 行为对齐（0 元积分单在创建订单内联结清）。

### 7.4 支付渠道抽象

```kotlin
interface PayChannel {
    val type: String                      // wxpay|alipay|point|deposit|offline|paypal(P2)
    fun prepay(trade: TradeDO, ctx: PayCtx): ChannelPayParams   // 返回 JSAPI 参数包/跳转串
    fun query(tradeId: String): TradeState
    fun refund(refund: AftersalesRefundDO): RefundResult
}
```

M0：`point`/`deposit`/`offline`（对公转账，走 `offline_payment` 审核流）为**真实现**；`wxpay`/`alipay` 提供 `MockChannel`（同构参数包+本地模拟回调）与 `SandboxChannel` profile，M1 替换正式 SDK（wechatpay-java / alipay-sdk-java）。回调统一入口 `TradeService.onChannelNotify`（§3.2 幂等模式）。

### 7.5 订单查询与详情

`getOrderDetail` = 主表 + items + 店铺信息 + trade 摘要 + 物流/自提核销码 + 状态文案（`OrderStatusMachine.descOf`），出参字段名对齐 PHP `orderInfo`（对照表在 URL 文档 §4.4，个别源系统 camel/snake 混用字段以源为准）。

### 7.6 促销/券（P0 子集）

- `MarketingEngine.onOrder(ctx)`：满减/满折按 `promotions_marketing_activity(+items)` 计算，规则 JSON（condition_type/condition_value）解析器 `RuleParser`——格式沿用 PHP `discount_config` 存量数据；
- `CouponService`：领取（总量 CAS `send_num<total_num`）、锁定（下单事务）、核销（支付后事件）、过期回收（@Scheduled）；`promotions_coupon_user.status` 状态机 UNUSED/LOCKED/USED/EXPIRED。
